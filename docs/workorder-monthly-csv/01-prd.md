# 工单报工 CLI — 按月统计与 CSV 导出 PRD（01-prd）

> 角色产出：产品经理。本文档为测试验收的产品判定依据；不涉及技术选型、代码文件与接口设计。
> 范围：仅覆盖新增的"按月统计"与"CSV 导出"两个功能域的最小可用版本；现有功能沿用 `docs/workorder/01-prd.md`（FR-1~FR-9 / AC-1~AC-15），不在本文档重新定义。
> 本目录 FR-x / AC-x 编号从 1 重新开始，编号贯穿后续环节（TASK-x / BUG-x / DEV-QUESTION-x）；具体命令形式与导出结果的获取方式以架构文档为准。

## 1. 背景与问题

现有系统已支持登记工单、逐笔报工与按日查询，但统计口径停留在"单日 / 单工单"：月末汇报产量时，统计员只能逐日查询再手工累加，既慢又易错；要做进一步分析（如用 Excel 筛选、透视）也没有机器可读的导出格式，只能复制粘贴纯文本。本期以最小可用方式补齐两个能力：按月合计统计、按月报工明细的 CSV 导出。

## 2. 目标用户与使用场景

- 目标用户不变：车间班组长、生产统计员；单人单机使用，无网络、无账号体系。
- 场景一（月度汇报）：月末统计员输入年月，直接读出当月报工笔数与合格/不良总数，快速准确向上汇报。
- 场景二（分析/存档）：统计员把某月全部报工明细导出为 CSV，用表格软件打开做筛选、透视或长期存档。

## 3. 用户故事

1. 作为统计员，我想要输入年月查看该月的报工合计（笔数、合格总数、不良总数），以便月末快速准确汇报产量。
2. 作为统计员，我想要把指定月份的全部报工明细导出为 CSV，以便用表格软件直接打开进行筛选、透视与存档。

## 4. 功能需求

**FR-1 按月统计（P0）**
输入一个年月（YYYY-MM），输出该月全部报工记录（跨工单）的合计：报工笔数、合格总数、不良总数。归集口径：按每笔报工自身的报工日期所属月份归集（与工单创建时间无关）；数量按记录实际值直接累加（既定"单笔超额报工不封顶"口径同样适用，不做封顶或剔除）。
约束：年月必填，须为 YYYY-MM 格式且月份有效（01–12）；非法输入明确报错、退出码非 0，不输出任何统计数字。不限制可查询的月份（过去/未来月份均可查，沿用系统"日期不做业务限制"既定口径）。该月无任何报工记录时输出空结果提示，不作为错误。

**FR-2 月度明细 CSV 导出（P0）**
输入一个年月（YYYY-MM），将该月全部报工记录导出为 CSV：
- 首行为表头，依次五列：日期、工单号、操作工、合格数量、不良数量。
- 每笔报工一行；行序与现有工单明细口径一致：先按报工日期升序，同日按录入先后。
- 字段值含逗号、双引号或换行时按通用 CSV 规则转义，保证常见表格软件解析后列数与字段值不失真。
- 该月无报工记录时仅输出表头行，不作为错误。
- 成功导出时除 CSV 内容本身外不混入任何提示性文字（导出结果可整体当作 CSV 解析）；失败时只输出错误、退出码非 0，不输出残缺 CSV。
约束：年月校验与 FR-1 相同。

**FR-3 输出与错误口径沿用（P1）**
新增功能沿用全系统既定输出口径：统计结果为纯文本；错误信息中文明确说明原因；错误退出码非 0。不改变既有命令行为与既有输出。

## 5. 非目标（本期不做）

1. 统计不下钻：不做按操作工、按工单、按日的分组统计或分项小计（仅月度总合计）。
2. 不做环比/同比、多月对比、图表、报表模板。
3. CSV 导出只做"指定月份报工明细"一种：不做月度汇总结果的 CSV、不做 Excel（.xlsx）等其它格式、不做字段/列自定义、不做多月份合并导出、不做任意日期范围导出。
4. 导出不做筛选：不提供按工单号/操作工筛选导出（整月全量）。
5. 不做数据导入、定时/自动报表、通知提醒。
6. 不改动既有功能行为与数据口径（对既有数据只读使用）。

## 6. 验收标准

前置约定（适用于全部 AC）：
- 未特别说明时，每条 AC 从空数据状态开始。
- "统计 / 导出"指本文档定义的两项功能操作，具体命令形式与导出结果的获取方式以架构文档为准。
- M1、M2 代表两个不同的年月（YYYY-MM）；D1、D2 代表同一月份内两个不同日期（YYYY-MM-DD，格式合法）。

**AC-1 月度合计正确**
输入：创建工单（计划 100），在 M1 内报工三笔：D1/张三/合格30/不良2，D1/王五/合格5/不良0，D2/李四/合格40/不良1。操作：统计 M1。期望：成功（退出码 0），输出该月报工笔数 3、合格总数 75、不良总数 3。

**AC-2 跨工单汇总**
输入：创建两个工单 W1、W2（各计划 100），M1 内报工：W1/D1/张三/30/2，W2/D2/李四/10/0。操作：统计 M1。期望：报工笔数 2、合格总数 40、不良总数 2（跨工单合并，不分工单展示）。

**AC-3 空月统计**
输入：M1 内已有任意一笔报工。操作：统计无任何报工的月份 M2。期望：输出空结果提示，退出码 0，不报错、不输出伪造数字。

**AC-4 非法月份拒绝（统计）**
操作：分别用以下输入统计：2026-13、2026-00、2026-1、202601、abc、缺省（不给年月）。期望：每次均明确报错、退出码非 0，不输出任何统计数字。

**AC-5 月份隔离**
输入：创建工单（计划 100），报工两笔：M1 内 D1/张三/30/0，M2 内 D2/李四/20/0。操作：分别统计 M1 与 M2。期望：统计 M1 输出笔数 1、合格 30、不良 0；统计 M2 输出笔数 1、合格 20、不良 0（互不混入）。

**AC-6 CSV 表头、行数与行序**
输入：承 AC-1 数据（M1 三笔）。操作：导出 M1。期望：首行为表头，依次含日期、工单号、操作工、合格数量、不良数量五列；数据行共 3 行，每行五个字段值与对应报工记录一致（含所属工单号）；行序为 D1 张三、D1 王五、D2 李四。

**AC-7 CSV 特殊字符转义**
输入：创建工单（计划 100），M1 内报工两笔：D1/操作工"张三,李四"/合格10/不良0，D1/操作工 王"五"/合格5/不良0（操作工名含英文逗号、英文双引号）。操作：导出 M1。期望：导出成功；含逗号/引号的字段按 CSV 通用规则转义（引号包裹、引号双写）；用 CSV 解析工具打开后每行仍为 5 列，操作工列分别为"张三,李四"与"王\"五\""原值，无串列、无失真。

**AC-8 空月导出**
操作：对无任何报工的月份 M2 导出。期望：仅输出表头一行、无数据行，退出码 0，不报错。

**AC-9 非法月份拒绝（导出）**
操作：分别用 AC-4 所列同类非法年月输入执行导出。期望：每次均明确报错、退出码非 0，不输出任何 CSV 内容（无表头、无数据行）。

**AC-10 导出内容纯净**
输入：承 AC-1 数据。操作：导出 M1，将全部输出整体按 CSV 解析。期望：恰为 1 行表头 + 3 行数据，除末尾换行外无空行、无提示语、无多余列（即除 CSV 内容外不含任何其它文字）。

**AC-11 既有功能不受影响（回归抽查）**
输入：承 AC-1 数据。操作：执行既有按日查询 D1 与工单列表。期望：与原 PRD 对应验收一致——D1 输出两笔（张三 30/2、王五 5/0，含工单号）；列表显示累计合格 75、累计不良 3、进度 75%、状态进行中。

**AC-12 Excel 中文兼容**
输入：承 AC-7 数据（操作工名含中文与特殊字符）。操作：在 Windows 上用 Excel 直接打开导出的 CSV。期望：中文显示正常无乱码；特殊字符字段显示为原始操作工名。判定方式以开放问题 Q-3 的裁决为准。

## 7. 开放问题（请需求方逐条拍板）

1. Q-1. CSV 导出的内容范围（推荐：指定月份报工明细逐笔导出，即本文档 FR-2 口径，明细可支撑自主筛选与透视；备选：仅导出月度统计汇总结果；备选：汇总与明细两种都提供）。
2. Q-2. 年月参数可否省略（推荐：不可省略，必须显式给 YYYY-MM，避免"当前月"随执行时间漂移造成脚本与测试歧义；备选：省略时默认系统当月）。
3. Q-3. CSV 与 Windows Excel 的中文兼容口径（推荐：导出为带 BOM 的 UTF-8，保证 Excel 直接打开中文不乱码；备选：不带 BOM 的 UTF-8，需经 Excel 导入向导手动指定编码）。
4. Q-4. 导出明细是否支持筛选（推荐：本期不做筛选、整月全量导出，保持最小规模；备选：沿用按日查询的工单号/操作工筛选参数）。
5. Q-5. 空月份数据的处理口径（推荐：统计输出空结果提示、导出仅含表头行，均不报错，与既有"空日查询不报错"口径一致；备选：空月份按错误处理并明确提示）。
