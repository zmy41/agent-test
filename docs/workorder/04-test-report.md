## 3. BUG 清单

### BUG-1：`WORKORDER_DATA_FILE` 指向不存在目录时，create/report 抛未捕获 ENOENT 异常（英文堆栈），违反 FR-9 明确报错要求

- **对应 AC**：AC-14 异常输入分支 + FR-9（错误信息明确说明原因，便于人与脚本读取）
- **复现步骤**（真实进程实测）：
  1. `$env:WORKORDER_DATA_FILE = "<目录>\no-such-sub\p.json"`（父目录 `no-such-sub` 不存在）
  2. 执行 `node workorder.js create 支架 100`
- **期望**：退出码 1，stderr 输出一行可区分的明确中文错误（形如 `错误：…`），不产生任何数据变更
- **实际**：进程抛未捕获异常 `Error: ENOENT: no such file or directory, open '…\no-such-sub\p.json'`（多行英文堆栈，出自 `store.js` 的 `save → writeFileSync`），退出码 1。自动化证据：`test/acceptance.test.js` 用例 35（AC-14 异常）失败，断言信息即该 ENOENT。旁证：同 env 下只读命令 `query` 正常返回空提示（退出码 0），说明仅"写盘"路径缺保护。
- **严重度**：**minor**（AC-14 正常路径不受影响；无数据损坏；属异常输入下的报错质量缺陷）
- **建议归属**：TASK-3（`store.save` 未处理写盘异常；亦可在 `run()` 编排层统一捕获 save 异常并转换为明确中文错误文案）

除 BUG-1 外未发现其他缺陷：AC-1~AC-13、AC-15 的全部正常/边界/异常用例，以及 AC-9 字节级"拒绝即无变更"、AC-2 序号扩位与跨日、AC-12 真实进程级重启均通过。

## 4. 覆盖说明

**无法自动化或以等价方式验证的点**：

1. **AC-2 可选项"系统日期真实变为次日"**：测试无法等待真实跨日，采用注入 `now` 模拟跨日（用例 6），并另以"不注入 now 的真实系统日期"用例（用例 2）验证 `formatDateKey` 真实路径；两者结合即等价覆盖。
2. **AC-12"结束程序后重新执行"**：采用两条更强路径——①同一数据文件连续多次 `run()`（每次重新读盘，设计 §4.5 声明的等价方式）；②`spawnSync` 两次真实独立 node 子进程（用例 29），后者即真实的进程级重启，无模拟。
3. **损坏判定为浅校验**（设计 §8 风险 3）：手工构造的字段级脏数据（如 okQty 为字符串）不在防护与测试范围（PRD 非目标）。
4. **未覆盖的物理场景**：磁盘写满、写权限拒绝、并发写（PRD 非目标 3 明示单机单人串行）；其中"写盘失败"的目录不存在场景已由 BUG-1 用例覆盖。
5. **设计既定口径（非缺陷，已按此验收）**：①query 传无效日期按错误处理、退出码 1（02-design §8 开放问题 1 既定裁决）；②detail 对 0 记录工单输出"聚合行 +（无报工记录）"两行（03-dev-notes §3-2）；③0 字节/纯空白的数据文件按"损坏"明确拒绝且不写回（裁决 3 推论，用例 38 已验证）；④只读命令（list/detail/query）不落盘、不凭空创建 data.json（03-dev-notes §3-1，用例 25/36/37 已验证）。
6. **FR-9 纯文本**：真实进程输出经检查不含 ANSI 转义序列（用例 29 断言）；输出分隔符与空结果文案按 02-design §4.1 既定口径比对。

**规模约束遵守**：仅新增 `test/acceptance.test.js`；框架为 Node 内置 `node:test`（`node --test` 执行），真实进程冒烟用内置 `node:child_process`，零第三方依赖；未修改/删除任何产品代码与既有测试，既有 41 用例回归全绿。
