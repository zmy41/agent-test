# 生产工单报工小系统 — PRD（01-prd）

> 角色产出：产品经理。本文档为测试验收的产品判定依据；不涉及技术选型、代码文件与接口设计。
> 范围：需求原文全部四个功能域（工单管理 / 报工 / 按日查询 / 数据持久化）的最小可用版本。

## 1. 背景与问题

小型生产场景中，工单与产出靠人工记录：进度不直观、合格/不良数量分散易错、按日追溯困难。需要一个单机即可用的最小报工系统：登记工单、逐笔报工、自动维护进度与状态、按日查询、数据长期留存。

## 2. 目标用户与使用场景

- 目标用户：车间班组长、生产统计员；单人单机使用，无网络、无账号体系。
- 典型场景：开工前创建工单 → 生产中逐笔报工 → 系统自动累计并流转状态 → 日终按日期核对当日全部报工（可按工单号/操作工筛选）→ 数据在重启后继续可用。

## 3. 用户故事

1. 作为班组长，我想要创建工单并自动生成不重复的工单号，以便免人工编号、快速登记任务。
2. 作为班组长，我想要在工单列表看到计划量、累计合格/不良、进度与状态，以便掌握各工单进展。
3. 作为统计员，我想要为指定工单录入一笔报工（日期、操作工、合格数、不良数），以便如实及时记录产出。
4. 作为班组长，我想要合格数达标后工单自动完工并拒绝后续报工，以便防止完工后误报。
5. 作为统计员，我想要按日期列出全部报工并可按工单号/操作工筛选，以便核对当日产出与责任。
6. 作为使用者，我想要数据重启后不丢失，以便长期连续使用。

## 4. 功能需求

状态词表（全系统唯一）：待开工 / 进行中 / 已完成。

**FR-1 创建工单（P0）**
录入产品名称与计划数量创建工单。约束：产品名称必填非空；计划数量必须为正整数。系统自动生成工单号，格式 `WO-YYYYMMDD-NN`：YYYYMMDD 为创建当日日期，NN 为当日序号，从 01 起按当日创建顺序递增、跨日重置（超过 99 时自然扩位）。初始状态一律为"待开工"。

**FR-2 工单列表（P0）**
列出全部工单，按工单号升序（等价于创建顺序）。每个工单显示：工单号、产品名称、计划数量、累计合格数、累计不良数、进度百分比、状态。进度百分比 = 累计合格数 ÷ 计划数量 × 100%，四舍五入取整；累计合格可因单笔超额报工超过计划，此时按实际显示（可 >100%），不封顶。

**FR-3 工单详情（P0）**
按工单号查看该工单的全部报工记录，按日期先后排序，同日按录入先后排序；每条记录含日期、操作工、合格数量、不良数量。工单号不存在时给出明确报错，不输出任何工单数据。

**FR-4 报工录入（P0）**
对指定工单录入一笔报工，字段：日期、操作工、合格数量、不良数量。约束：操作工必填非空；日期必填且须为有效日历日期，格式 YYYY-MM-DD（本 PRD 最小约定）；合格/不良数量须为 ≥0 的整数且不得同时为 0。报工成功后立即保存，并在列表/详情中即时反映。

**FR-5 状态自动流转（P0）**
状态仅由系统按报工结果自动流转，不提供手工改状态：任一笔成功报工使"待开工"变为"进行中"；当该笔报工后累计合格数 ≥ 计划数量，状态在该笔报工后即为"已完成"（允许从"待开工"一笔直达"已完成"）。"已完成"的工单再报工必须拒绝。

**FR-6 非法报工拒绝（P0）**
以下情形必须拒绝并给出可区分的明确报错，且不产生任何数据变更（累计数、记录数、状态均不变）：
① 合格或不良数量为负数；② 合格或不良数量为非整数；③ 合格与不良同时为 0；④ 工单号不存在；⑤ 工单已完工。

**FR-7 按日查询（P0）**
按日期列出该日期的全部报工记录（跨工单），每条含工单号、操作工、合格数量、不良数量。可按工单号筛选、可按操作工筛选，两者可同时使用（须同时满足才命中）。无匹配记录时输出空结果提示，不作为错误。

**FR-8 数据持久化（P0）**
全部数据（工单与报工记录）保存在本地单个数据文件（JSON 格式，需求既定），操作成功后即写入。重启程序后数据完整可读。默认数据文件为运行目录下 `data.json`；可通过环境变量 `WORKORDER_DATA_FILE` 覆盖数据文件路径。（此两项命名为需求原文既定的用户可见配置，非本阶段设计。）

**FR-9 纯文本输出（P1）**
全部输出为纯文本，不含图形/颜色；错误信息明确说明原因，便于人与脚本读取。

## 5. 非目标（本期不做）

1. 工单的编辑、删除、取消、暂停/恢复；不提供任何手工状态变更。
2. 报工记录的修改、删除、冲销（报工一经成功不可变）。
3. 用户、登录、权限；多机共享与并发写控制（按单机、单人串行使用设计）。
4. 统计报表、导出（CSV/Excel）、图表、通知提醒。
5. 数据备份、恢复、迁移、历史数据导入。
6. 报工日期的业务限制（不限制补录过去/预录未来，仅校验日期合法）。
7. 交互式菜单/向导界面；只做一次性命令式操作。

## 6. 验收标准

前置约定（适用于全部 AC）：
- 未特别说明时，每条 AC 从空数据状态开始（无数据文件或空数据文件）。
- "创建 / 报工 / 列表 / 详情 / 按日查询"指需求定义的五项功能操作，具体命令形式以架构文档为准。
- 文中日期均为 YYYY-MM-DD 格式的有效日历日期，D1、D2、D3 代表不同日期。

**AC-1 创建成功与初始状态**
输入：产品名称"支架"、计划数量 100。操作：创建工单。期望：成功并输出新工单号，格式 `WO-〈创建当日日期〉-01`；列表中该工单显示：支架、100、累计合格 0、累计不良 0、进度 0%、状态待开工。

**AC-2 当日序号递增**
输入：当日连续创建两个工单（产品 A、B）。操作：依次创建。期望：第 2 个工单号为 `WO-〈当日〉-02`，两个工单号不同；（可选）系统日期变为次日后再创建，新工单号日期部分为次日、序号为 01。

**AC-3 创建非法输入拒绝**
操作：分别用以下输入创建工单：产品名称为空；计划数量 0、-5、2.5、abc。期望：每次均拒绝并给出明确报错；工单总数不变。

**AC-4 报工成功与列表聚合**
输入：创建工单（计划 100）；两笔报工：D1/张三/合格30/不良2，D2/李四/合格40/不良1。操作：创建后依次报工。期望：两笔均成功；列表显示累计合格 70、累计不良 3、进度 70%、状态进行中。

**AC-5 详情内容与排序**
输入：创建工单（计划 100）；按顺序三笔报工：D1/张三/30/2、D2/李四/40/1、D1/王五/5/0。操作：查看工单详情。期望：输出 3 条记录，顺序为 D1 张三、D1 王五、D2 李四（先按日期、同日按录入先后）；每条含日期、操作工、合格数、不良数。

**AC-6 工单号不存在**
输入：不存在的工单号（如 WO-19990101-99）。操作：分别对其执行报工与详情。期望：均明确报错"工单不存在"；数据无任何变化。

**AC-7 达标自动完工并拒绝后续报工**
输入：创建工单（计划 100）；报工 D1/张三/100/0。操作：报工成功后，再对该工单报工 D2/李四/1/0。期望：首笔成功且状态自动变为"已完成"；第二笔被拒绝，报错指明工单已完工；累计合格仍为 100、记录仍 1 条。

**AC-8 单笔超额报工**
输入：创建工单（计划 100）；报工 D1/张三/合格120/不良0。操作：报工一次。期望：报工成功，状态"已完成"，累计合格 120，进度显示 120%。

**AC-9 非法报工逐项拒绝**
输入：一个进行中的工单。操作：分别尝试报工：合格=-1；合格=1.5；不良=-2；合格=0 且不良=0；日期=2026-02-30；日期=abc；操作工为空。期望：每项均拒绝，报错能区分对应原因（负数 / 非整数 / 同时为 0 / 日期无效 / 操作工缺失）；该工单累计数、记录数、状态均不变。

**AC-10 按日查询（全部与空日）**
输入：承 AC-4 数据（D1 一笔、D2 一笔）。操作：查询 D1；再查询 D3（无记录日）。期望：查询 D1 仅输出 D1 那笔（张三、工单号、30、2）；查询 D3 输出空结果提示且不报错。

**AC-11 按日查询筛选**
输入：D1 两笔报工：工单 W1/张三/30/2，工单 W2/李四/10/0。操作：① 查询 D1 且按工单号 W1；② 查询 D1 且按操作工"李四"；③ 查询 D1 且同时给工单号 W1 + 操作工"李四"。期望：① 仅张三那笔；② 仅李四那笔；③ 空结果提示（不报错）。

**AC-12 重启后数据保留**
输入：创建工单并完成两笔报工。操作：结束程序后重新执行列表与详情（视为重启）。期望：工单、状态、累计合格/不良、全部报工记录完整保留且数值一致。

**AC-13 默认数据文件位置**
操作：不设置覆盖环境变量，在运行目录执行创建工单。期望：运行目录下生成默认数据文件 `data.json`，其中包含该工单数据。

**AC-14 覆盖数据文件位置**
操作：设置环境变量 `WORKORDER_DATA_FILE` 指向新路径 P，执行创建工单；再以同一变量查询。期望：数据写入 P；默认 `data.json` 不被创建/修改；以同一变量再次执行可读到该工单。

**AC-15 空数据列表**
操作：空数据状态下执行工单列表。期望：输出空列表提示，不报错、不输出伪造数据。

## 7. 开放问题（请调度者裁决）

1. 单笔报工使累计合格数超过计划数量：PRD 默认允许（随即完工、进度按实际可 >100%，见 FR-2 / AC-8）；如需改为"不得超过剩余计划数量"请裁决。
2. 报工日期：PRD 默认允许补录过去与预录未来（仅拒绝非法日期）；如需限制范围请裁决。
3. 数据文件存在但内容损坏：PRD 默认明确报错且不覆盖、不重建（交人工处理）；文件不存在则按空数据启动。请确认。
